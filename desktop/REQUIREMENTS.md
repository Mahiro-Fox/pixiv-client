# Pixiv Client（桌面端）需求文档

- 文档版本：v1.0
- 对应代码：`desktop/`（Electron + React + TypeScript + Tailwind）
- 文档定位：描述当前已实现的功能范围与行为约定，用于验收、迭代与后续扩展对齐

---

## 1. 项目概述

一款运行在 Windows 桌面的 Pixiv 作品批量抓取与下载工具。用户配置作者 ID、标签、保存目录与 Cookie 后，可抓取该作者指定标签下的全部作品，在列表中选择需要的作品批量下载，并支持暂停、断点续传、失败重试与本地已下载判定。

区别于脚本版（仓库根目录的 Python 实现），桌面端提供图形界面、可视化进度、下载队列持久化，以及针对 pixiv 限流（429）的全局请求治理。

### 1.1 目标用户

- 需要批量备份某位画师作品的用户
- 需要按标签批量收集素材的用户
- 希望有图形界面、能中断续传，而不是命令行脚本的用户

### 1.2 技术形态

- Electron 45 主进程 + React 19 渲染进程，TypeScript
- 界面使用 Tailwind + 手写 shadcn/ui 风格组件
- 网络请求走 Electron `net` 模块，直接复用系统网络栈并注入 Cookie / UA / Referer
- 打包运行：开发模式 `npm run dev`，构建 `npm run build`

## 3. 功能需求

### 3.1 配置管理

**入口**：左侧抓取面板（组件 `CollectPanel`，只放爬取相关参数）；下载质量、保存目录、文件名模板、Cookie 等全局设置在顶栏「设置」按钮打开的设置弹窗（`SettingsDialog`）中。

**作品来源**

| 来源 | 说明 | 主要参数 |
| --- | --- | --- |
| 作者标签 | 抓取指定画师在指定标签下的作品 | 用户 ID、标签 |
| 我的收藏 | 同步某个账号的收藏夹 | 收藏用户 ID（留空使用当前登录账号）、收藏类型（公开/私密）、可选标签 |

**字段与约束**

| 字段 | 说明 | 取值范围 / 默认值 |
| --- | --- | --- |
| 用户 ID | pixiv 用户 ID（作者标签来源）；必填，界面标签带红色 `*`，为空时禁用「抓取作品列表」 | 数字字符串，默认 `114638697` |
| 收藏用户 ID | 收藏夹所属账号；留空则读取当前登录账号 | 数字字符串，默认空 |
| 收藏标签 | 收藏夹接口级标签过滤，留空表示全部 | 字符串，默认空 |
| 收藏类型 | 公开收藏 / 私密收藏 | `show` / `hide`，默认 `show` |
| 标签 | 作者标签来源的作品标签（作为主标签） | 字符串，默认 `R-18` |
| 附加包含标签 | 多标签组合的额外包含标签，逗号/空格/顿号分隔 | 字符串，默认空 |
| 排除标签 | 多标签组合中需要排除的标签 | 字符串，默认空 |
| 组合方式 | 多标签之间「同时满足（AND）」或「任一满足（OR）」 | `and` / `or`，默认 `and` |
| 起始偏移 | 从第几个作品开始抓取（用于跳过已处理部分） | ≥ 0，默认 0 |
| 每页数量 | 单次接口请求条数，同时作为作品列表的翻页步长 | 1–100，默认 48 |
| 并发数 | 同时解析/下载的任务数 | 1–32，默认 8 |
| 请求间隔（秒） | 每个任务开始前的额外等待，用于进一步降速 | 0–5，默认 0.2 |
| 下载质量 | 常规图（约 1200px）/ 高清原图（作品原始尺寸） | `regular` / `original`，默认 `regular` |
| 保存目录 | 下载根目录，必须是绝对路径 | 默认开发模式为 `../pixiv_downloads`，打包后为「下载/pixiv_downloads」 |
| 文件名模板 | 落盘文件名格式，支持 9 个变量 | 默认 `{id}_p{page}_{title}` |

**行为**

- 配置写入 `userData/config.json`；点击「抓取作品列表」或「下载选中作品」时会先保存当前表单值；关闭「设置」「过滤规则」弹窗时也会立即落盘。
- 下载质量可在左栏下载按钮上方与设置弹窗中切换，两处共用同一份配置。
- 任务快照会记录创建时的下载质量，断点续传时未解析的作品沿用该质量。
- 保存目录支持「选择目录」系统对话框与「打开目录」。
- 保存目录必须是绝对路径，否则下载前直接报错，不会开始任务。
- 保存目录下的子目录名：作者标签来源使用标签名，收藏夹来源固定为 `收藏夹`。

### 3.2 Cookie 管理

**入口**：顶栏「设置」弹窗中的 Cookie 区域，以及顶部 Cookie 状态徽标。

**需求**

- **应用内登录（推荐方式）**：点击「登录 pixiv」打开独立登录窗口（`BrowserWindow`，`partition: persist:pixiv-login`），用户在窗口内完成 pixiv 账号登录，成功后自动读取会话 Cookie 并保存，全程不涉及解密浏览器数据。
  - 登录窗口与主界面 session 隔离；分区持久化，已登录状态下再次打开无需重输密码。
  - 全局通过 `app.userAgentFallback` 设置 UA，Chromium 版本取运行时真实值（`process.versions.chrome`）。两个必须点：UA 里不能出现 `Electron/x.y.z` 和 app 名，否则 reCAPTCHA 直接判为嵌入式客户端而陷入无限图片验证；且必须用 fallback 而非 `webContents.setUserAgent()` / `session.setUserAgent()`——后两者都不会传播到跨站 OOPIF，而 reCAPTCHA 恰好跑在 `recaptcha.net` 的 iframe 里。另关闭 `AutomationControlled` 消除自动化标记。
  - 窗口内的外链（帮助、条款等）交由系统浏览器打开。
  - 受 Google 政策限制，嵌入窗口内无法完成 Google / Twitter 等第三方登录（会提示 unverified app）。界面文案引导用户改用 pixiv 邮箱或 ID 密码登录；仅使用第三方登录的账号走「手动粘贴」。
  - 登录成功判定：导航到 `*.pixiv.net` 且非 `accounts.pixiv.net`，且会话中存在 `PHPSESSID`。
  - 只取 `PHPSESSID`，不把浏览器侧的追踪 Cookie 写入应用配置。
  - 用户直接关窗视为取消，已保存的 Cookie 保持不变，并给出提示。
  - 同一时间只允许一个登录窗口，重复点击复用同一次结果。
- **手动粘贴（兜底方式）**：支持粘贴 `PHPSESSID=...` 或完整 Cookie 字符串后保存。
- 只填 PHPSESSID 值时自动补全为 `PHPSESSID=...`；多行输入会合并为 `key=value; key=value` 形式。
- Cookie 来源优先级：环境变量 `PIXIV_COOKIE` > 用户数据目录的 `pixiv_cookie.txt` > 开发模式下的仓库根目录 `pixiv_cookie.txt`。
- 界面展示来源（环境变量/本地文件/未配置）与脱敏后的值。
- 配置 Cookie 后自动调用用户信息接口识别当前登录账号（昵称 + ID），用于收藏夹同步。
- 「下载选中作品」在未配置 Cookie 时禁用，因为未登录状态下 R-18 作品会被 pixiv 过滤。
- **不读取系统浏览器（Chrome/Edge）的 Cookie**：Chrome 127 起启用 App-Bound Encryption，密钥绑定浏览器自身进程，第三方程序即便读到密文也无法解密；Google 还在推进 DBSC（设备绑定会话凭据）。此外读取浏览器凭据属于杀软重点拦截行为，不做也不建议做。

### 3.2.1 App API 凭据（OAuth，写操作用）

**入口**：设置弹窗「App API 凭据（写操作）」区块。

**背景**：pixiv 的写操作（收藏、关注）只挂在 `app-api.pixiv.net`，认证方式是 `Authorization: Bearer {access_token}`，与读取数据用的 `www.pixiv.net` + Cookie 是两套体系。因此额外需要一层 OAuth 凭据。

**需求**

- 凭据分两部分：
  - `client_id` / `client_secret`：pixiv 官方 Android 客户端的内置常量，随 APK 分发、公开可得、不绑定账号。程序内置默认值（`shared/appClient.ts`），设置里留空即用内置；也可覆盖，以便常量被轮换或封禁时无需改代码。只填其中一个会被拒绝。
  - `refresh_token`：属于用户账号的真实秘密，只保存在本地 `userData/oauth.json`，可手填或经登录授权自动获取。
- 保存即校验：点击「保存并验证」时先调用 `POST https://oauth.secure.pixiv.net/auth/token`（`grant_type=refresh_token`）刷新一次，成功才落盘，失败则原凭据不变并就地显示原因。
  - `invalid_grant` → 「refresh_token 无效或已被吊销，请重新导入」。
  - `invalid_client` → 「client_id 或 client_secret 不正确」。
- access_token 在过期前 60 秒自动续期；pixiv 每次刷新会下发新的 `refresh_token`，需同步更新落盘。
- 并发去重：多个写操作同时触发续期时只发一次刷新请求。
- token 端点要求 Android 客户端 UA（`PixivAndroidApp/...`），不能沿用网页 UA。
- App API 的 401 不得触发「Cookie 失效」提示，两者互不影响。
- 状态展示：已连接时显示 pixiv 用户 id 与 refresh_token 后四位；未连接时显示说明文案。
- 清除凭据需二次确认；清除只影响写操作，不影响 Cookie 与读取能力。
- 请求节流：App API 默认 800ms 冷却（429 上报后延长），批量收藏 / 关注必须串行，不能像只读接口那样并发。

**当前边界**

- 本轮只落地凭据层（获取、校验、续期、清除）与设置界面；收藏 / 关注的实际请求与按钮尚未接入，见 [SHELVED.md](./SHELVED.md) 的「OAuth 层已实现」与「下一步」。
- 未实现 PKCE 授权码登录（官方网页登录拿不到 refresh_token，需从已有客户端或抓包获得）。

### 3.3 作品抓取

**入口**：左侧「抓取作品列表」/「同步收藏夹」。

**需求**

- 作者标签来源：调用 pixiv 标签作品接口，按 `起始偏移`、`每页数量` 拉取首页，随后按总数补齐剩余分页。
- 收藏夹来源：调用收藏夹接口，按 `收藏用户 ID` + `收藏类型` 分页拉取；`收藏用户 ID` 留空时自动使用当前登录账号，未登录则报错提示。
- 收藏夹可按「收藏标签」过滤（接口级过滤，留空表示全部）。
- 抓取过程中显示：已抓取数量/总数（已完成页数/总页数）。
- 结果按作品 ID 去重，保持接口返回顺序。
- 分页级失败不阻断整体：记录失败页数，完成后提示「N 个分页抓取失败，列表可能不完整」。
- 抓取结果为空时提示检查来源参数（用户 ID / 收藏用户 / 收藏类型 / 标签 / Cookie）。
- 翻页并发最多 3 路，实际节奏由全局 API 限速闸门控制，降低 429 概率。
- 抓取会重置作品列表、清空预览、回到第 1 页，并重新扫描本地已下载状态。
- 默认选中「当前筛选结果第一页」的作品。

### 3.4 收藏夹同步（增量）

**入口**：作品来源切换到「我的收藏」后点击「同步收藏夹」。

**需求**

- 支持公开收藏与私密收藏；私密收藏需要有效 Cookie。
- 「只同步未下载的作品」默认开启：抓取完成后自动开启「只看未下载」筛选，列表只保留本地缺失或页数不全的作品，实现增量同步。
- 默认全选的对象是「按过滤规则 + 只看未下载筛选后的第一页」，因此一键下载即为新增内容。
- 收藏夹作品统一存放到 `{保存目录}/收藏夹/{作者ID}_{作者名}/`，不随收藏标签变化。
- 收藏夹来源下标签输入用于接口级过滤；作者标签来源下标签用于指定画师的作品标签。

### 3.5 过滤规则

**入口**：顶栏右侧的「过滤规则」图标按钮（生效规则数量以角标显示），点击打开独立弹窗；下载工作台的作品列表工具栏保留同一个入口，并额外显示「规则过滤 N」。

**生效范围**

| 页面 | 是否生效 | 说明 |
| --- | --- | --- |
| 插画 / 漫画搜索、收藏、用户主页 | ✅ | 结果网格 `SearchWorkGrid` 内部统一按规则过滤 |
| 排行榜、推荐（作品） | ✅ | 同一个网格组件，含触底续拉 |
| 小说搜索 | ✅ | 分级 / 标签 / 关键词 / 屏蔽生效；页数与尺寸规则不适用（改用正文字数，暂未提供 UI） |
| 用户搜索、关注列表、推荐画师 | ✅ | 只按屏蔽规则过滤用户卡 |
| 下载工作台 | ✅ | 抓取结果在渲染层过滤，与上面同一份实现 |
| 浏览记录 / 稍后看 | ❌ | 本地数据，且屏蔽后卡片要留着才能右键取消屏蔽 |
| 本地图库 / 小说书库 | ❌ | 磁盘上的既有文件不受显示规则影响 |

**规则项**

| 规则 | 说明 | 默认 |
| --- | --- | --- |
| 最少页数 | 作品总页数下限，0 不限 | 0 |
| 最多页数 | 作品总页数上限，0 不限 | 0 |
| 最小宽度 | 原图宽度下限（接口未返回宽度时不参与判断），0 不限 | 0 |
| 最小高度 | 原图高度下限，0 不限 | 0 |
| 内容分级 | 全部 / 仅 R-18 / 排除 R-18 | 全部 |
| 排除 AI 作品 | 按接口的 AI 标记过滤 | 关闭 |
| 排除关键词 | 匹配标题与作者名，逗号/空格/顿号分隔，不区分大小写 | 空 |
| 排除标签 | 匹配作品标签，同时兜底匹配标题与作者名 | 空 |

**行为**

- 规则在本地实时生效（纯前端计算），改完弹窗里任何一项，所有页面的列表立即重算，不重新请求接口。
- 推荐页例外（仅内容分级）：作品来自 App API 推荐，接口不提供分级维度，本地「内容分级」规则不参与判定，其余规则（页数 / 尺寸 / 排除标签 / 排除关键词 / 屏蔽标签 / 屏蔽用户 / AI）照常生效。实现上由网格传 `ignoreRating`，插件式地以 `r18=any` 重新编译一次规则；过滤弹窗在 `/recommend` 时把该下拉置灰并说明原因，切回其它页面恢复可编辑，配置值照旧保留；顶栏过滤徽标的计数也按当前页生效项计算。
- 多条规则之间是「与」关系，任意一条不满足即排除。
- 判定只有一份实现：`src/shared/filters.ts` 的 `compileFilters` / `workPasses` / `novelPasses`；渲染层通过 `lib/filterContext.tsx` 的 `useFilteredWorks` / `useFilteredNovels` 取用（Provider 由 App 包住路由，配置一变自动重算），工作台的 `applyWorkFilters` 委托到同一份实现。
- 一页结果被规则全部挡掉时，网格显示「本页 N 个结果已被过滤规则隐藏」并提供「调整规则」按钮，不会只留一片空白。
- 下载工作台的列表顶部显示「规则过滤 N」；过滤图标显示当前生效的规则条数；分页、全选、只看未下载均基于过滤后的结果。
- 配置随 `config.json` 持久化；弹窗底部「清空」可一键恢复默认，关闭弹窗即保存配置。

#### 全局屏蔽（标签 / 用户）

**入口**：过滤弹窗内的「屏蔽标签」「屏蔽用户」两个输入框；过滤弹窗底部的「管理屏蔽名单」按钮打开屏蔽管理弹窗。

- 与上面的「排除标签」不同：屏蔽是全局的，搜索结果、用户主页、收藏浏览、批量同步与下载全部生效，改完后已加载的列表也会立即重算。
- 屏蔽标签按整标签不区分大小写匹配；屏蔽用户支持「用户 ID 精确匹配」或「作者名包含」，逗号 / 空格 / 顿号分隔。
- **屏蔽管理弹窗**（`components/BlockManagerDialog.tsx`）：分「屏蔽的用户」「屏蔽的标签」两组列出全部词条，每行标注匹配方式（用户 ID 精确 / 昵称包含 / 整标签），逐行可「取消屏蔽」，整组可「清空」（二次确认）；纯数字用户 ID 附带「在 pixiv 打开主页」。空组显示虚线占位与添加方式说明。弹窗只做查看与删除，添加仍走右键菜单和输入框。
- 取消屏蔽：管理弹窗逐条删除；作品卡 / 用户卡右键菜单在作者已被屏蔽时，把「屏蔽该作者」换成「取消屏蔽该作者」，删掉命中该作者的全部词条（ID 与昵称都写过时一起删）。
- 屏蔽只在本地生效：不调用任何 pixiv 屏蔽 / 静音接口，不改变账号状态，pixiv 网页与其它客户端照旧显示。取消屏蔽后需要刷新列表（重新搜索 / 翻页）才会重新出现，已取回的列表不会自动重抓。
- 主进程在返回作品前统一过滤（`src/shared/block.ts` 的 `filterBlocked`），渲染层再兜一层，保证「界面上看到的」和「能下载的」一致。
- 规则随 `config.json` 持久化，并计入过滤图标上的生效规则条数。

### 3.6.1 结果排序与清单导出

- CSV 带 UTF-8 BOM 与单元格转义；JSON 为同字段的对象数组。
- 导出成功显示绿色提示条与完整路径；取消保存不提示。

### 3.10 下载执行

**入口**：左侧「下载选中作品（N）」。

**流程（两阶段）**

1. **解析阶段**：并发请求每个选中作品的分页接口，得到每张图的下载地址、原始尺寸与目标路径；单个作品解析失败只记录「解析失败」，不中断任务。
2. **下载阶段**：并发下载每张图片；目标文件已完整存在且满足当前质量时记为「已存在」并跳过，尺寸不满足时重新下载覆盖，日志记为「覆盖」。

**需求**

- 未选中作品、未配置 Cookie、保存目录非法时禁止开始。
- 同时运行的下载任务数由「并行任务数」控制（1–4），超出额度的任务排队等待；同一作者在队列中重复入队会被拒绝。
- 下载质量按当前配置选择：`regular` 使用常规图地址，`original` 使用高清原图地址；对应字段缺失时互相回退。
- 常规图与高清原图共用同一文件名，已存在文件按像素尺寸校验（读取 PNG/GIF/JPEG 文件头，不整图解码）：
  - 选择 `original`：已有文件尺寸与作品原始尺寸不一致（典型是长边 1200 的常规图）时覆盖重下；
  - 选择 `regular`：已有任意成品都视为满足，避免把已有的原图降级覆盖成小图；
  - 尺寸未知（旧队列快照、动图成品）或无法解析时退回「存在即跳过」。
- 动图（ugoira）作品通过 `ugoira_meta` 接口取得帧压缩包地址，按单文件下载；保存格式由设置中的「动图格式」决定：
  - `zip`：直接落盘帧压缩包；
  - `mp4` / `gif`：先把 zip 下载到同目录 `.ugoira-{id}.zip` 临时文件，解压后用随包 ffmpeg 转码，成功后原子重命名为目标文件并删除临时 zip。
- 下载使用 `.part` 临时文件，成功后原子重命名为正式文件（支持 `.jpg/.png/.gif/.zip/.mp4` 等；普通图片按 URL 后缀推断，动图按目标格式指定，缺省 `.jpg`）。
- 单文件失败自动重试；确定性 4xx 不重试；429 触发全局冷却后重试，且不计入失败。
- 中止（暂停）时立即停止取新任务，已完成的文件保留。
- 任务结束后返回汇总：阶段、计数、字节数、用时、输出目录、是否暂停。

### 3.11 进度反馈

**入口**：右侧「下载任务」标签页顶部的总进度卡片 + 下方每个任务卡片。

**需求**

- 总进度卡片只保留一条汇总进度条与百分比：按队列中所有未完成任务的「已完成图片数 / 总图片数」计算；同时显示任务数、已下载字节与最长用时。
- 阶段：等待开始 / 解析分页 / 下载中 / 已暂停 / 已完成。
- 解析阶段按「已解析作品数/总作品数」计算百分比；下载阶段按「已完成图片数/总图片数」计算。
- 每个任务独立显示同样的统计维度：成功、已存在、失败、解析失败、已下载字节、用时，以及该任务自己的进度条与百分比；折叠时也保留进度条一行。
- 下载进行中每秒刷新用时。
- 任务完成或暂停时记录结束时间，界面「用时」随之固定，不因切换标签页等重渲染而继续增长。
- 出现限流时显示提示徽标：`接口/图片限流冷却中 Ns（并发 X）` 或 `已自动降速：接口并发 X`。
- 卡片底部常驻一行并行提示：`当前并行任务数 N，需要同时运行更多任务请点击这里前往设置调整`，点击直接打开设置。
- 未开始下载时展示引导文案。

### 3.12 队列持久化与断点续传

**入口**：右侧「下载任务」标签页的「未完成任务」卡片；每个任务卡片自带暂停 / 继续按钮，左侧面板不再提供全局暂停。

**任务快照**

- 位置：`userData/queue.json`。
- 内容：任务 ID、标签、保存目录、作品根目录、状态、创建/更新时间、作品快照、每张图片任务（作品 ID、URL、目标路径、相对标签、状态、字节数、错误）、作品解析失败记录、进度计数、作者 ID 与作者标签。
- 写入策略：临时文件 + 重命名原子写；更新防抖 500ms；退出前强制执行并落盘。
- 状态：排队中 / 解析中 / 下载中 / 未完成（暂停）/ 已取消 / 失败 / 已完成；已完成且无失败项的任务会从队列中移除。
  - **未完成**：用户暂停或软件退出，可原地继续；
  - **已取消**：用户取消，已下载的文件全部保留，卡片显示「重新开始」；
  - **失败**：跑完但有失败项（下载失败 / 解析失败 / 熔断中止），或启动前校验失败（模板非法、未配置 Cookie、目录非法），卡片折叠态直接显示原因摘要。
- 三种结束态必须能一眼分开：以前「取消 / 暂停 / 跑完但有失败」全部落成 paused，界面上完全一样，用户没法判断该点「继续」还是该看失败清单。
- 上次运行中未完成的任务、以及重启时仍在排队的任务，一律视为「未完成」；已取消与失败是稳定状态，重启后原样保留（失败清单也保留）。

**续传规则**

- 已完成（成功/已存在）且文件仍存在的图片直接跳过；文件被删除的重新排队。
- 上次失败的图片重置为待下载并重试。
- 已有任务记录的作品不重复解析分页，只解析新增作品。
- 续传时进度计数从快照恢复，不从头开始。
- 退出应用时先中止运行中的任务、以「已暂停」状态落盘，再退出。

**界面**

- 每个未完成任务显示作者标识（单作者为「用户 ID-画师名」，如 `10000001-xxx`；多作者任务为「N 位作者」）、标签与作品数、状态徽标、独立的进度条与完成比例、失败数。
- 展开后显示成功 / 已存在 / 失败 / 解析失败 / 已下载字节 / 用时六项统计、待下载数、失败详情、导出清单、移除、打开目录。
- 暂停 / 取消 / 继续：运行中显示「暂停」，展开后另有「取消」，都只作用于该任务本身（其它任务继续跑）。
- 结束态的按钮按状态区分：未完成 →「继续」或「重试失败项 N」；已取消 →「重新开始」；失败 →「重试」或「重试失败项 N」。三者都走同一条续传逻辑（已完成图片不重复下载）。
- 任务卡片默认折叠，只显示作者、状态与进度条；点卡片或右侧箭头展开。
- 任务列表顺序固定为入队先后（按创建时间），并行任务的实时进度更新不会让卡片互换位置。

### 3.12.1 多任务并行下载

**入口**：设置 → 请求限流 → 「并行任务数」。

**需求**

- 并行任务数 1–4，默认 2；1 表示串行（与旧行为一致）。
- 下载入口改为「入队」：点击后立即把任务快照写入队列并返回，不再等待整个下载结束；主进程按并行额度自动依次启动排队任务。
- 队列为空时按钮文案为「下载」，队列里已有未完成任务时变为「添加到任务队列」，额度已满也不禁用（新任务排队等待）。
- 重复任务按作者拦截：作品全部来自同一作者时，若队列里已有该作者的任务（含已暂停的），入队直接报错「已存在 `用户 ID-画师名` 用户的任务」；多作者任务（收藏夹/多标签）不做此校验。
- 主进程按 `jobId` 维护运行表，同时运行的任务数不超过上限；批量同步同样占用一个额度。
- 进度事件与日志条目带 `jobId`，界面据此区分不同任务的进度，互不覆盖。
- 未完成任务里每个任务自带暂停 / 继续；运行中只中止自己，不影响其它任务。
- 进度卡片在同时运行 ≥2 个任务时显示「同时运行 N 个任务」。
- 左侧面板不再有全局暂停按钮；批量同步是长任务、不进队列，其取消入口在进度卡片的批量提示条里。
- 退出应用时中止全部运行任务并以「已暂停」状态落盘；重启后排队中的任务同样视为「已暂停」，需手动继续。

### 3.12.2 失败重试中心

**入口**：右侧「未完成任务」卡片中的失败相关按钮。

**失败清单**

- 两类失败统一汇总：作品解析失败（没有分页任务）与图片下载失败（单张原图）。
- 清单项包含：类型、作品 ID、文件相对路径（或作品名）、图片地址、错误原因。
- 解析失败记录随任务快照持久化，因此在重启后仍可查看与重试。
- 图片失败直接由任务状态 `failed` 推导，不额外存一份，避免状态不一致。

**重试**

- 「重试失败项」复用队列续传逻辑：失败的图片重置为待下载，解析失败的作品重新解析分页，成功/已存在的不重复下载。
- 重试前会清空该作品旧的解析失败记录，避免同一错误重复累积。
- 重试过程与正常续传一致，进度从快照恢复，实时写入日志与进度卡片。

**失败详情**

- 按需加载（展开时才请求），按「解析 / 下载」标签区分类型。
- 显示总数与逐条错误原因，最多展示 40 条高度内滚动。
- 每条失败右侧提供「重试」按钮，逐条重试：只把该条失败项重置（图片按地址、解析按作品 ID），其余失败项保持原失败状态，不连带重试。
- 确定性失败（404 作品已删除、403 没有权限）在清单里标注「重试也不会成功」，仍允许手动点一次，但自动重试直接跳过。
- 逐条重试与正常下载同样占用额度：额度已满时重试仍可提交（进入排队），但该任务自身运行中时其重试按钮禁用；结束后自动刷新失败清单，重试成功的条目从清单消失。
- 若任务仍有残留失败项，任务不会被误判为「全部完成」而从队列移除。

### 3.12.3 自动重试与熔断

**为什么不只靠传输层重试**：`http.ts` 的重试是几秒内连打 4 次，遇到短时限流或代理抖动往往还没恢复就已经放弃了；连续失败的文件全堆在「失败清单」里等用户手动点，体验很差。

**任务级重试**

- 每个文件在传输层之外还有 2 次「整体重来」机会（共 3 个任务级尝试），间隔 2s / 5s 递增；429 优先用服务端给的冷却时间。
- 判定按错误类别走（`main/pixiv/retry.ts`）：`rate-limit`（429/408）、`network`（超时、连接中断、代理不可用）、`server`（5xx）→ 值得重试；`auth`（401）、`forbidden`（403）、`missing`（404/410）→ 一次就放弃，重试只会放大限流。
- 传输层降到 2 次尝试，两层叠加最多 6 次请求，失败更快冒到任务层，用更长的退避替换密集的短重试。
- 每个文件记录实际尝试次数（`QueueTask.attempts`），便于排查「一直失败」的具体文件。

**连续失败熔断**

- 连续 8 项系统性失败（`auth` / `network` / `server` / `rate-limit` / `unknown`）后停止启动剩余任务，任务落成「失败」，原因写作「连续 N 项失败，已中止剩余任务」。
- 只统计「本该成功却失败」的类别：收藏夹里几十个作品被删除（404）属于正常数据老化，不会触发熔断。
- 熔断后剩余文件保持「待下载」，修好 Cookie / 代理后点「重试」即可接着下，已下载文件不重复下载。

**已知限制**：并行下载时「连续」是近似值（多个 worker 同时失败会更快触发），阈值 8 留了足够余量。

**导出清单**

- 导出为 CSV，系统保存对话框默认落到「下载」目录，文件名带时间戳。
- 列：类型、作品ID、文件/作品、图片地址、错误原因；单元格做引号转义，文件带 UTF-8 BOM，Excel 打开中文不乱码。
- 导出成功后界面出现绿色提示条，展示完整保存路径；取消保存不提示。

### 3.14 文件名模板

**入口**：顶栏「设置」按钮打开的设置弹窗（与保存目录同属全局设置）。

**变量**

| 变量 | 含义 |
| --- | --- |
| `{id}` | 作品 ID（必填） |
| `{page}` | 页码，从 0 开始，与 pixiv 一致 |
| `{page1}` | 页码，从 1 开始（与 `{page}` 二选一） |
| `{title}` | 作品标题 |
| `{author}` | 作者名 |
| `{userid}` | 作者 ID |
| `{tag}` | 当前标签目录名（收藏夹为「收藏夹」） |
| `{date}` | 发布日期 `YYYY-MM-DD` |
| `{quality}` | 下载质量，`regular`（常规图）或 `original`（高清原图） |
| `{ext}` | 扩展名（如 `.jpg`） |

**规则**

- 模板必须包含 `{id}` 与页码变量之一，否则多作品/多页会重名；校验不通过时输入框下方红字提示，并禁用「下载选中作品」。
- 模板不能包含路径分隔符；目录固定为 `{标签}/{作者ID}_{作者名}/`。
- 变量值中的 `\ / : * ? " < > |` 与换行制表符替换为 `_`，并去掉首尾的点、空格、下划线。
- 空变量（如无发布日期）留下的连续下划线/短横自动折叠，避免出现 `__`。
- 未写 `{ext}` 时自动追加扩展名；整体文件名超过 120 字符时截断。
- 预览区用样例数据实时渲染，`{ext}` 变量与模板编辑均即时生效；「恢复默认」回到 `{id}_p{page}_{title}`。
- 「已下载」判定按当前模板解析文件名中的作品 ID 与页码，**同时兼容默认模板**，因此改模板不会让历史文件变成未下载。
- 切换模板后，新下载按新模板命名；已完成的任务快照保留原有路径，续传不会重命名。
- 模板含 `{quality}` 时，同一页的常规图与高清原图各自落盘、互不覆盖；模板不含时沿用「按尺寸校验」策略：已有原图视为已下载，已有常规图在下载原图时被覆盖升级，下载常规图时不降级覆盖。

### 3.15 已下载判定（严格校验）

**需求**

- 依据保存目录下 `{标签}/{作者目录}/`（收藏夹来源为 `收藏夹/{作者目录}/`）中的文件名统计：默认 `{作品ID}_p{页码}_{标题}{扩展名}`，或当前配置的模板。
- 只有作品 `0 ~ pageCount-1` 的每一页都存在成品文件，才判定为「已下载」。
- `.part` 临时文件不计入。
- `pageCount` 未知（≤0）时退化为「存在任意一张成品图」。
- 选择高清原图时，还会校验作品首页文件的像素尺寸是否等于原图尺寸；长边 1200 的常规图会被判定为「未下载」（切换质量后自动重新扫描）。模板含 `{quality}` 时同一页可能存在两份文件，任意一份尺寸达标即视为已下载。
- 判定时机：抓取作品列表后、下载任务结束（完成或暂停）后、切换下载质量后、开启「只看未下载」时。

### 3.17 限流治理（429）

**背景**：解析与翻页都走接口，聚合请求速率超过 pixiv 对单 IP 的限制时返回 429，单纯加大每任务间隔效果有限。

**需求**

- 全局按类别限速：接口类（API）与图片 CDN 类分别限制并发与最小请求间隔，默认接口 2 并发 / 650ms，图片 6 并发 / 120ms。
- 翻页并发额外限制为最多 3 路。
- 收到 429 时：
  - 优先读取 `Retry-After`（秒数或 HTTP 日期）；
  - 对整类请求设置全局冷却，无 `Retry-After` 时按指数退避（起点约 2.5s，上限 45s）并加抖动；
  - 下调该类别并发（每次 -2，最低 1）；
  - 429 不计入失败，重试次数：接口 5 次、图片 4 次。
- 连续成功 8 次后逐级恢复并发。
- 冷却与降速状态通过事件推送到界面展示。

#### 3.17.1 限流参数面板

**入口**：设置弹窗 →「请求限流」。

**需求**

- 五个可调参数：接口并发（1–8）、接口最小间隔（100–2000ms，步进 50）、图片并发（1–16）、图片最小间隔（50–1000ms，步进 10）、并行任务数（1–4，步进 1）。
- 使用加减步进器而非自由输入，取值始终收敛在合法区间；「恢复默认」一键回到 2/650、6/120、并行 2。
- 修改后关闭设置弹窗即落盘并立即作用于主进程限速器（无需重启、无需等下一次下载）；下次启动自动加载。
- 429 的自动冷却与临时降并发逻辑不变：冷却结束后仍逐步恢复到用户设定的并发上限。

### 3.18 多标签组合搜索

**入口**：左栏「抓取设置」→「多标签组合」区块（附加包含标签、排除标签、组合方式）。

**需求**

- 在主标签之外可追加多个包含标签，并选择两种组合方式：
  - **同时满足（AND）**：作品标签需同时包含主标签与所有附加标签；
  - **任一满足（OR）**：作品标签包含主标签或任意一个附加标签即可。
- 「排除标签」中的任意一个出现在作品标签里，该作品被丢弃。
- 标签以芯片形式输入：回车/逗号添加，退格删除最后一个，带 pixiv 关联标签建议。
- 抓取策略（为控制请求量）：
  - AND：只用第一个包含标签调用接口，其余标签在本地按作品返回的 `tags` 过滤；
  - OR：按每个包含标签依次抓取（顺序执行，不叠加并发），合并去重后再过滤；
  - 收藏夹来源同样生效：收藏标签为空时先抓取全部收藏，再本地按标签筛选。
- 作品没有返回标签信息时保留作品，避免静默漏抓。
- 组合标签只影响抓取结果，不改变落盘目录：目录仍按主标签（收藏夹为「收藏夹」）命名。
- 对比：本地「过滤规则」中的「排除标签」是对已抓取结果的后置过滤；这里是在抓取阶段缩小结果集。

### 3.19 动图（ugoira）支持

**入口**：无需单独入口；列表、详情与下载流程自动识别动图作品。

**需求**

- 作品列表接口返回 `illustType = 2` 时视为动图，卡片与详情弹窗显示「动图」徽标。
- 详情弹窗只预览封面帧，并提示下载结果为设置中选择的动图格式。
- 解析阶段调用 `/ajax/illust/{id}/ugoira_meta` 取得 `originalSrc` / `src` 作为 zip 地址与 `frames`（文件名 + 毫秒时长），按单个文件加入下载任务。
- 保存格式由全局设置「动图格式」决定：`MP4 视频` / `GIF 动图` / `保留压缩包`，缺省 MP4；左栏下载区与设置弹窗文案同步说明。
- 转码使用随包 `ffmpeg-static`（6.1.1，打包时通过 `asarUnpack` 解包；也可用环境变量 `FFMPEG_PATH` 指定）。帧顺序与每帧时长来自接口 `frames`：concat 清单按 `delay / 10ms` 把同一帧重复若干份，再以 `-r 100` 读入，避免 image2 默认 1/25 时间基把短帧量化成 40ms：
  - MP4：`libx264` + `yuv420p` + `-video_track_timescale 1000` + `+faststart`，奇数宽高自动裁成偶数；
  - GIF：`palettegen` / `paletteuse` 生成调色板，避免颜色失真，每帧延迟精确到 1/100 秒；
  - 缺少 ffmpeg 时自动退回 `zip`，不中断整批下载；转码失败只影响该作品并记入失败清单。
- 文件按当前文件名模板命名，动图扩展名按目标格式固定为 `.mp4` / `.gif` / `.zip`；`.part` + 原子重命名等落盘规则与普通图片一致。
- 已下载判定沿用严格校验：模板解析出该作品 `p0` 文件即视为已下载；动图成品不做像素尺寸校验。
- 任务快照记录 `ugoiraFormat`，断点续传沿用创建时的格式；失败重试、失败清单与日志对动图任务同样生效。
- 图库扫描把 `.zip` / `.mp4` / `.gif` 均识别为动图成品，且不作为封面与图片预览来源。

- 下载完成或修改保存目录后自动失效缓存，下次进入图库即为最新结果。
- 主进程递归监听保存目录（`fs.watch({ recursive: true })`，事件合并 800ms 防抖）：外部新增、删除、重命名文件后自动向界面推送 `library:changed`，图库静默刷新（不闪加载态），无需手动「重新扫描」；监听失败（目录不存在/权限不足）时静默降级，仍可手动刷新。

### 3.23 网络代理

**入口**：设置弹窗 →「网络代理」。

**需求**

- 单套代理配置，统一作用于主界面接口请求、图片下载与 pixiv 登录窗口；主进程分别对 `defaultSession` 与 `persist:pixiv-login` 分区调用 `session.setProxy`。
- 支持协议：HTTP、HTTPS、SOCKS4、SOCKS5；主机与端口必填，端口范围 1–65535。「HTTPS」指与代理本身建立 TLS 连接（代理端需支持），本地 v2rayN / Clash 的混合端口属于普通 HTTP 代理，应选 HTTP；选错会报 `ERR_PROXY_CONNECTION_FAILED`。
- 关闭代理时使用系统代理（`mode: 'system'`）；开启时使用固定代理（`mode: 'fixed_servers'`）。
- 支持「不走代理的地址」（Chromium `proxyBypassRules` 语法，逗号分隔，如 `localhost, 127.0.0.1, <local>`），默认 `<local>`。
- HTTP / HTTPS 代理支持账号密码认证：遇到 407 时由主进程的 `login` 回调提供凭据。登录窗口等 webContents 请求走 app 级 `login` 事件，`net.request`（接口与图片下载）走请求对象自身的 `login` 事件。
- Chromium 不支持 SOCKS4 / SOCKS5 的用户名密码认证，选择这两类协议时界面禁用账号与密码输入并给出提示。
- 密码不写入 `config.json`：使用 `safeStorage` 加密保存到 `userData/proxy_password.bin`，渲染层只能拿到 `hasPassword`；系统不支持加密时退化为仅当前用户可读的明文文件。
- 修改后立即应用并断开旧连接（`closeAllConnections`），无需重启；应用启动时在建窗口之前应用已保存的配置。
- 「测试连接」用与真实接口相同的请求头（UA / Referer / 已保存 Cookie）通过当前代理请求 `https://www.pixiv.net/`：能收到 HTTP 响应即视为代理链路正常，4xx / 5xx 单独提示为「代理已连通但 pixiv 拒绝请求」（多为出口 IP 或 UA 风控），只有网络层失败（超时、连接被拒、代理认证失败）才判为连接失败。
- 设置面板显示 Chromium 解析出的实际路由（`session.resolveProxy`，如 `PROXY 127.0.0.1:10808`、`DIRECT`），用于确认代理是否真正生效，而不是只看开关状态。
- 配置保存在 `config.json` 的 `proxy` 字段；旧配置缺少该字段时逐项补齐默认值，避免浅合并产生 `undefined`。

### 3.31 写操作（收藏 / 关注 / 取关）

**需求**

- 全部走 pixiv App API（`app-api.pixiv.net`），需要先在设置中连接 OAuth 凭据；未连接时相关按钮不渲染，不发请求。
- 作品收藏：打开详情弹窗时用 `GET /v2/illust/bookmark/detail?illust_id=` 读取状态；「收藏」→ `POST /v2/illust/bookmark/add`（`illust_id`、`restrict`），「已收藏」→ `POST /v1/illust/bookmark/delete`（`illust_id`）。
- 可见性：公开 / 私密分段控件，未收藏时作为收藏时的 `restrict`，已收藏时切换会重新提交 add 更新可见性。
- 画师关注：用户主页用 `GET /v1/user/detail?user_id=` 的 `is_followed` 初始化；「关注」→ `POST /v1/user/follow/add`（`user_id`、`restrict=public`），「已关注」→ `POST /v1/user/follow/delete`（`user_id`）。自己的主页不显示按钮。
- 小说收藏：阅读页顶栏「收藏 / 已收藏」按钮，与作品收藏一致带公开 / 私密分段控件。状态读 `GET /v2/novel/bookmark/detail?novel_id=`，该接口不可用时退回 `GET /v1/novel/detail?novel_id=` 的 `novel.is_bookmarked`；「收藏」→ `POST /v2/novel/bookmark/add`（`novel_id`、`restrict`），「已收藏」→ `POST /v1/novel/bookmark/delete`（`novel_id`）。已收藏时切换可见性会重新提交一次 add。
- 小说系列追更：小说系列页的「追更 / 已追更」按钮。网页接口（`/ajax/novel/series/{id}`）不返回追更状态，因此单独读 `GET /v1/novel/series?series_id=` 的 `novel_series_detail.watchlist_added`；切换走 `POST /v1/watchlist/novel/add`、`/v1/watchlist/novel/delete`（`series_id`）。状态读不到时按「未追更」渲染，不阻断页面。
- 写通道（`appApi.ts: appApiPost`）：表单编码 + Android UA + Bearer；非 2xx 读取响应体，401 / 403 翻成中文提示；与读取用的 Cookie 体系互不影响。
- 操作进行中按钮禁用并显示转圈；失败时在弹窗 / 用户页显示错误文案，不改变已显示的状态。
- 凭据获取：设置页支持两种方式——手工填入三项后「保存并验证」；或填好 client_id / client_secret 后点「通过 pixiv 登录获取」，走 PKCE 授权码流程自动换来 refresh_token 并保存。
  - 授权页 `https://app-api.pixiv.net/web/v1/login?code_challenge={S256}&code_challenge_method=S256&client=pixiv-android`，复用 Cookie 登录窗口分区，已登录过无需再输密码。
  - 主进程拦截 `web/v1/users/auth/pixiv/callback?code=`，用 `grant_type=authorization_code` + `code_verifier` + `redirect_uri` 到 `oauth.secure.pixiv.net/auth/token` 换取令牌；关窗或拒绝授权视为取消，不改动已保存凭据。
  - Cookie 换成不了 refresh_token（pixiv 没有这种端点），但授权窗口与 Cookie 登录共用分区，已登录时打开授权页会直接跳回 callback，可在隐藏窗口中静默完成。
- 登录后自动授权：Cookie 登录成功后自动静默跑一次 PKCE；6 秒内等不到回调才把窗口显示出来交给用户处理；已连接则跳过；成功后经 `oauth:changed` 事件让界面立即刷新凭据状态。
- IPC：`write:bookmarkState`、`write:setBookmark`、`write:followState`、`write:setFollow`、`write:novelBookmarkState`、`write:setNovelBookmark`、`novelSeries:watchState`、`novelSeries:watch`。

### 3.32 稍后看（本地待看列表）

**入口**：顶栏图标（`/watch-later`）；作品详情弹窗页脚的「稍后看」按钮。

**背景**：pixiv 没有「稍后看」概念，Pixeval 的 WatchLater 也是本地持久化。因此本功能是**纯本地列表**，与 pixiv 收藏（写服务端、分公开/私密）相互独立：收藏是长期归档，稍后看是「先记下、回头再看」的临时书签。

**需求**

- 存储：`userData/watchLater.json`，结构 `{ version, entries[] }`，与浏览记录同样采用 800ms 防抖 + 临时文件重命名的原子写入，退出前由 `flushWatchLater()` 强制落盘；上限 2000 条。
- 条目字段：作品 id、标题、作者 id / 昵称、250px 缩略图、页数、xRestrict、illustType、加入时间。缩略图在主进程统一收敛成 `c/250x250_80_a2`。
- 幂等：重复加入同一作品只更新时间并置顶，不产生重复条目；读盘时按 id 去重、按时间倒序。
- 详情弹窗：打开时读一次 `isWatchLater(id)`；点「稍后看」加入 → 按钮变为「已加入稍后看」；再点一次移出。该按钮**不依赖 OAuth**，未连接 App API 时依然可用。
- 列表页：按加入时间倒序，关键词过滤（标题 / 作者 / 作品 ID），分页（每页 24），点击卡片打开应用内预览；卡片右上角「移出」按钮（悬停显示）；支持二次确认清空。
- IPC：`watchLater:list`、`watchLater:state`、`watchLater:add`、`watchLater:remove`、`watchLater:clear`；add / remove 均返回最新完整列表，前端直接替换状态。

**不做**：与 pixiv 收藏互相同步、跨设备同步、自动清理已下载条目。

### 3.33 系列聚合浏览（漫画 / 插画系列）

**入口**：作品详情弹窗标题下的「所属系列《…》第 N 话」；路由 `/series/:seriesId`。

**需求**

- 作品详情接口（`/ajax/illust/{id}`）的 `seriesNavData` 映射为 `WorkSeriesNav`，随作品数据一路带到详情弹窗；无系列时接口可能返回空对象 `{}`，缺 `seriesId` 即视为不在系列中。
- 系列详情优先走 App API `GET /v1/illust/series?illust_series_id=`（`filter=for_android`），按 `next_url` 翻页取完整目录；`illust_series_detail` 提供标题、简介、作者、封面、话数、完结状态与 `watchlist_added`。
- 未连接 App API 或 App API 请求失败时，用当前作品页的 `seriesNavData` 兜底（`workId` 由详情入口带进 URL），只显示当前这一话，页面顶部提示「连接凭据后可浏览完整目录并追更」。
- 追更：已连接 App API 时显示「追更 / 已追更」按钮，走 `POST /v1/watchlist/manga/add|delete`（`series_id`）；未连接时不渲染按钮。
- 页面结构：返回按钮 + 封面与元信息（标题、完结状态、作者、话数、简介、操作按钮）+ 话列表网格；点任意一话打开应用内作品预览。
- IPC：`series:detail`、`series:watch`。

**不做**：小说系列在此页复用（小说已有 `/novel/series/:seriesId`）、系列追更列表页。

### 3.34 列表页离开再回来保留数据

**问题**：从列表页点作者 / 作品进入详情页，再返回时列表页会重新挂载并重新请求，用户丢失刚才浏览的那批数据与滚动位置。

**方案：keep-alive + 已加载标记 + 滚动位置 hook**。依赖 `keepalive-for-react` / `keepalive-for-react-router` v6。

- `App.tsx` 用一个**不带 path 的布局路由**包住全部页面，其元素 `KeepAliveOutlet` 渲染 `KeepAliveRouteOutlet`；缓存容器必须不随路由卸载，否则缓存随之丢失。
- `include` 只放六个浏览页：`/recommend`、`/illust`、`/manga`、`/novel`、`/ranking`、`/users`，`max={12}`。本地数据页（收藏 / 浏览记录 / 稍后看等）刻意不缓存，避免看到过期内容。
- `activeCacheKey={location.pathname}`：改筛选 / 翻页 / 回车搜索只改 search 参数，复用同一个组件实例，由页面自己的 effect 重新请求，不会生成一堆带不同 search 的缓存节点。
- **刷新时机**：顶栏搜索只在回车提交时刷新；`lib/searchSubmit.ts` 维护全局提交序号，`submitSearch` 每次提交都 `bumpSearchSubmit()`，序号进入搜索页的 effect 依赖，因此同一关键词再按一次回车也会重新请求。
- **推荐页切标签 / 切插画漫画不二次请求**：作品按 `kind` 分桶（`WorksBucket { works, next, token }`），`token = kind:连接状态`，命中就跳过请求；画师用 `usersLoaded` 布尔标记。只有用户点「刷新」才删掉当前桶并重取。kind 或凭据变化会让标记不匹配，从而自动重取。
- **后台页面不读全局 URL**：keep-alive 缓存的页面在后台并未卸载，`useSearchParams()` 读到的仍是全局当前位置。进详情页时 URL 没有 `word` / `page`，后台页面会把这些参数算成空值并触发 effect——返回时参数又变回来，于是再跑一遍，表现为「点进作者、返回后搜索页重新请求」。`lib/pageActive.ts` 的 `usePageActive()` 在 effect 首行判断，后台一律不做任何请求或清空；推荐页、插画、漫画、小说、用户、排行榜六页都已接入。
- **请求签名**：各页把「取数据的条件」字符串（含 kind/word/筛选/页码/提交序号）交给 `lib/usePagedQuery.ts` 的 `usePagedQuery`，由它用 ref 保存已加载签名并对齐页码：签名一致直接跳过，请求失败时清空签名以便下次激活或改参数重试。这样从详情页返回时参数即使短暂抖回也会被拦下（见 3.36）。
- **搜索框同步只在搜索栏目页**：`App.tsx` 只在 `/illust`、`/manga`、`/novel`、`/users` 四个 pathname 上用 URL 的 `word` 回填输入框；进 `/user/:id` 等详情页时 URL 没有 `word`，不做同步，避免输入框被清空后再跳回。
- **切到其它栏目再回来要保留原样**：顶栏「推荐 / 排行榜」的 URL 里没有 `word`，若按当前 URL 拼栏目链接，从它们回到插画 / 漫画 / 小说 / 用户时会把已经搜过的词、页码与筛选全部丢掉（表现为搜索框被清空、列表也空了）。`lib/sectionQuery.ts` 按栏目在内存里记住最后一次的查询串（`location.search`），顶栏栏目导航优先还原它；该栏目没有记录时才退回当前关键词，保留「换栏目继续搜同一个词」的原有行为。
  - 例：`/illust?word=A&page=3` → 推荐 → 点「插画」，回到的仍是 `/illust?word=A&page=3`；keep-alive 实例、已取到的数据与滚动位置都不变，不重新请求。
  - 各栏目互不影响：插画记 `A`、小说记 `B`，来回切换各回各家。
  - 记录只放内存，重启即失效，与 keep-alive 缓存、滚动位置的策略保持一致。
- **滚动位置**：库本身不做滚动恢复。`src/renderer/src/lib/scrollMemory.ts` 导出 `useKeepAliveScroll(key)`（回调 ref + 挂载还原 + `useLayoutEffectOnActive` 激活还原，rAF 兜底）与 `useScrollMemory(key)`（非缓存页面用）。**`ref` 必须挂到真正滚动的容器上**：页面外层 `main` 往往只是 flex 容器，实际滚动的是内部 `overflow-y-auto` 元素，挂错位置读到的 `scrollTop` 永远是 0。推荐页与排行榜的滚动容器确实是外层 `main`（推荐页把列表包一层 `shrink-0`，防止内部 grid 在 flex 收缩下变成独立滚动区）；插画 / 漫画 / 小说 / 用户四页挂在内层 `overflow-y-auto` 列表容器上。
- **滚动键按内容切换**：推荐页用动态键 `recommend:works:{kind}` / `recommend:users`，切标签或切插画漫画时直接还原新键的位置，两个列表各自停在自己的老位置。位置只在滚动事件里实时记录，**不要在切键时补读 `scrollTop`**：此时 React 已换上新的列表内容，旧列表更长的话 `scrollTop` 会被 clamp，补读反而把真实位置覆盖成 0（表现就是切回去总在顶部）。
- 数据整批重置（改筛选 / 翻页 / 刷新 / 换 kind）时调 `reset()` 回到顶部；`reset` 同时把记忆归零，避免下次挂载又跳回去。
- 该库要求关闭 `React.StrictMode`（`main.tsx` 已移除），否则开发模式下缓存节点挂载 / 卸载次数翻倍。
- 代价：keep-alive 只看路由与 pathname，**从别的栏目点导航回到已缓存页面不会重新请求**，需要新鲜数据时用页面上的「刷新」。
- 缓存与滚动位置都只在内存里，重启应用即失效；不写磁盘。

### 3.35 卡片右键菜单

作品卡与用户卡支持右键唤出操作菜单（`components/ContextMenu.tsx` + `lib/cardMenu.tsx`），卡片上不再需要堆放常驻图标。

- **作品卡**：应用内预览、在 pixiv 打开、查看作者主页、加入下载队列、加入 / 移出稍后看、复制作品链接、复制作品 ID、屏蔽该作者（该作者已被屏蔽时改为「取消屏蔽该作者」）。
- **用户卡**：打开主页、在 pixiv 打开、复制主页链接、复制用户 ID、屏蔽该作者（同上，已屏蔽时显示取消屏蔽）。
- **浏览记录 / 稍后看**：卡片不是 `SearchWorkCard`，但同样接了这套菜单（先转成 `SearchWork` 再唤出），右键即可加入下载或复制链接。
- 菜单渲染到 `document.body` 的 portal 上：卡片本身带 `overflow-hidden`（缩略图圆角），就地渲染会被裁掉一半；打开后先测量真实尺寸再收敛进视口，右下角右击也不会跑出屏幕。
- 关闭时机：点击别处（捕获阶段监听 `pointerdown`，避免被子元素的 `stopPropagation` 拦掉）、Esc、滚动、窗口失焦、缩放。`↑` / `↓` 在菜单项之间移动焦点。
- **动作自己读配置**：菜单挂在卡片内部、拿不到 App 的状态，所以每条动作各自 `getConfig()` 后执行；复制、入队、屏蔽的结果用 `lib/toast.ts` 的轻提示反馈（`<Toaster />` 挂在 App 根部）。
- 加入下载走 `download:enqueue`，与左栏下载共用同一个队列与并行额度；入队后由 `queue:changed` 广播刷新任务页。
- 屏蔽作者写入 `config.blockUsers`（优先写用户 ID，改名也不失效），写完广播 `pixiv:config-changed`：App 收到后重读一次配置——否则 App 内存里的旧 `config` 会在下次下载前 `setConfig(config)` 时把刚加的屏蔽项覆盖掉。
- 屏蔽只影响之后的请求（搜索、用户主页、收藏、下载），当前列表不会立刻消失，需要重新抓取或翻页。
- **取消屏蔽**：菜单打开时与「是否已在稍后看」一起读一次屏蔽状态（`isAuthorBlocked`），据此决定菜单项是屏蔽还是取消屏蔽（图标 `ShieldCheck` / 文案「取消屏蔽该作者」，且不再标红）。取消时按 `blockedUserTerms` 找出命中该作者的全部词条删除——用户可能是按昵称屏蔽的，也可能 ID 与昵称都写了，删的必须是命中项而不是作者全名。
- 屏蔽后该作者的作品卡会被主进程整体过滤掉，右键菜单通常够不着，因此过滤弹窗里的「管理屏蔽名单」（见 3.5）才是稳定的取消入口；浏览记录 / 稍后看用的是本地数据，卡片仍在，右键即可撤销。

### 3.36 统一分页与取数 hook

七个列表页此前各抄一份「页码 + 条件签名 + alive 标志 + loading/error + 滚动回顶」的骨架，现收敛到 `lib/usePagedQuery.ts`：

- `usePagedQuery<T>({ page, signature, query, skip?, scroll?, onData? })` → `{ data, loading, error, reload }`
  - 内置 `usePageActive()`：keep-alive 后台不读全局 URL、不发请求；
  - 签名 = `signature | page | nonce`，一致直接跳过（从详情页返回不重取）；
  - `skip` 用于「没关键词 / 没选用户 / 没连凭据 / 看别人的私密收藏」等场景，同时清空数据与错误；
  - 条件变化或翻页时调 `scroll.reset()` 回顶；`reload()` 用 nonce 强制重取（排行榜「刷新」按钮）；
  - `onData` 承载派生状态：筛选 chip 缓存、每页条数推算、总数等；
  - `query` / `onData` / `scroll.reset` 都用 ref 取最新值，页面里直接写内联函数也不会造成重复请求。
- `useLocalPage<T>(items, pageSize)` → `{ page, lastPage, pageItems, setPage, reset }`：给浏览记录 / 稍后看这类「一次取回整表、本地过滤分页」的页面用；列表变短时页码自动收敛，不会停在空白页。
- 已接入：插画 / 漫画搜索、用户搜索、排行榜、收藏浏览、我的关注、用户主页（远程取数）；浏览记录、稍后看（本地分页）。
- `clearOnChange` 只在「换对象」的页面打开（用户主页切作者），列表页不打开，避免换条件时白屏闪烁。
- `lib/errors.ts` 的 `messageOf` 同时取代了各页重复的「剥 IPC 错误前缀」函数。
- 新增列表页时优先复用：只要给出 `page`（URL 或 state）、条件签名和取数函数即可，不需要再手写 effect 与去重逻辑。

## 4. 非功能需求

### 4.1 性能

- 作品列表上千条时，分页切片与筛选在渲染层完成，避免一次渲染全部卡片。
- 缩略图懒加载；图片加载失败降级为占位符。
- 下载写盘流式进行，不整文件驻留内存。

### 4.2 稳定性

- 网络请求统一超时 30s；中止信号可随时取消请求与写盘。
- 配置文件、Cookie、队列文件均使用原子写或容错读取，损坏时回落默认值。
- 单个作品/单张图片的失败不影响其他任务。

### 4.3 安全

- 渲染进程通过 preload 暴露受限 API（`window.pixiv`），不开启任意 IPC。
- Cookie 仅在界面脱敏展示，存于用户数据目录，不写入日志。
- 下载目录由用户显式选择，且必须是绝对路径。

### 4.4 兼容性

- 目标平台：Windows 桌面（当前仅在此验证）。
- 网络层依赖系统/Electron 网络栈；直连不可达时可在设置中启用应用内代理。

## 6. 界面结构

- **顶栏**：应用名与副标题、插画 / 用户 / 小说 / 排行榜 / 推荐 路由切换、工作台 / 图库 / 书库 图标入口、全局搜索、账号菜单（关注列表 / 收藏 / 浏览记录 / 设置）、Cookie 状态徽标、打开保存目录。
- **左栏（380px，`CollectPanel`）**：作品来源切换、抓取参数、多标签组合、下载质量、抓取/关注/下载按钮（暂停由任务卡片负责，左栏不提供全局暂停）。
- **右栏**：错误提示条 → 三个标签页（作品列表 / 下载任务 / 下载日志）。
  - 「作品列表」工具栏含过滤图标、排序、导出、只看未下载、全选本页、分页条；
  - 「下载任务」顶部是总进度卡片（一条汇总进度条 + 百分比），下方是未完成任务卡片列表：每张卡片显示作者标识、状态、独立进度条，可折叠展开查看六项统计、失败详情、导出、移除、打开目录与暂停/继续，整页单层滚动；
  - 标签标题显示条目数角标（作品数 / 未完成任务数 / 日志条数）；
- **图库页（/gallery）**：先展示作者列表，进入作者后工具栏含搜索、标签筛选、排序、返回、重新扫描。

- 进度与队列不再常驻在标签页上方：主区高度全部留给当前标签内容，切换标签不影响后台下载。
- **小说页（/novel）**：搜索页为「搜索栏 + 筛选行 + 结果列表 + 相关标签侧栏」；系列页为「封面与元信息 + 操作按钮 + 章节目录」；阅读页为「固定工具栏（返回/进度/阅读设置/目录/保存）+ 正文滚动区 + 目录侧栏」，正文区按主题切换底色，阅读设置浮层含字号 / 行高 / 宽度 / 主题。
- **收藏页（/favorites）**：顶部工具条（用户 ID + 读取 / 我的收藏 / 公开私密切换 / 标签筛选）、当前标签提示、卡片网格与分页。
- **浏览记录页（/history）**：标题与说明、关键词搜索、清空（二次确认）、缩略图卡片网格（标题 / 作者 / 相对时间）与分页。
- **排行榜页（/ranking）**：工具条（插画 / 漫画、日期、最新一期、刷新）、榜单类型切换、榜单日期与总数提示、带名次的卡片网格与分页。
- **推荐页（/recommend）**：工具条（作品 / 画师、插画 / 漫画、已加载数量、刷新）、App API 提示条、作品网格或画师卡片列表；列表底部触底自动续拉，滚动区末尾显示加载指示。
- **弹窗**：作品详情与多图预览、应用内全屏图片预览（缩放/旋转/翻转）、关注列表选择、过滤规则（顶栏全局入口，含屏蔽名单管理）、设置（外观与语言、下载质量、动图格式、请求限流、网络代理、保存目录、文件名模板、Cookie）。
- **右键菜单**：作品卡 / 用户卡右键唤出 portal 菜单（预览 / 打开 pixiv / 查看作者 / 加入下载 / 稍后看 / 复制 / 屏蔽或取消屏蔽作者），随视口自动收敛；动作结果以窗口底部居中的轻提示反馈，成功 2.2s、失败 4.2s 自动消失，也可点关闭。

## 7. 边界与暂不包含

当前版本不包含：

- 关注画师的定时同步、排行榜之外的其它作品来源（如约稿、特辑）
- 失败项的手动编辑（逐条重试已支持）
- 点赞、转发、评论等社交互动（作品 / 小说收藏、画师关注、系列追更已支持，见 3.31）
- 收藏夹增量同步的定时任务（当前为手动点击同步）
- 关注列表的排序（搜索已支持，当前按 pixiv 默认关注顺序）
- 断点续传单张图片的 HTTP Range 续传（按文件粒度重下）
- 下载历史与统计报表（已提供 `history.json` 元数据索引与本地图库，暂不做统计报表）

上述暂不包含项与其它延后需求统一记录在 [SHELVED.md](./SHELVED.md)，后续排期从该清单取用。

## 8. 验收要点

1. 配置变更后重启应用，参数保持；保存目录非法时拒绝下载并提示。
2. 未配置 Cookie 时下载按钮禁用；配置后顶部徽标与设置弹窗均显示已配置与脱敏值。
3. 抓取 100+ 作品时进度实时更新，分页失败有提示，列表去重且顺序稳定。
4. 列表分页可切换、页码正确、默认第 1 页且默认选中第一页作品；「全选本页」只影响本页。
5. 点击卡片可预览全部页面图片，Esc 关闭；弹窗内可加入下载。
6. 标签输入 2 字符后出现建议，可用键盘选择，点击外部关闭。
7. 「只看未下载」只显示缺页作品；补齐所有页后徽标变为已下载。
8. 下载中途暂停，任务出现在「未完成任务」；关闭应用再启动可「继续」，已完成图片不重复下载。
9. 下载日志实时记录成功/已存在/失败及原因。
10. 连续快速抓取触发 429 时，界面显示冷却倒计时，冷却结束后任务继续且不被计为失败。
11. 配置 Cookie 后设置弹窗显示当前登录昵称与 ID；切到「我的收藏」时可留空收藏用户 ID 直接同步。
12. 收藏夹同步默认开启「只同步未下载」，二次同步时已完成的作品不再出现在默认选中范围内。
13. 过滤规则即时生效：调整页数、分级、排除标签/关键词后列表数量与「规则过滤 N」同步变化，勾选范围随之收缩。
14. 过滤规则清空后恢复全部作品；配置重启后保持。
15. 点击「从关注列表选择画师」可读取并分页浏览关注列表，头像正常显示，外链可打开 pixiv 主页。
16. 点击任意关注用户后弹窗关闭，用户 ID 被回填，并自动开始抓取该画师的作品列表。
17. 制造失败（如断网或删除文件后中断）后，「未完成任务」显示失败与解析失败数量，按钮变为「重试失败项 N」。
18. 展开失败详情能看到逐条类型、文件、错误原因；重试只处理失败内容，已成功的不重复下载，成功后失败计数归零。
19. 导出清单生成 CSV，Excel 打开中文正常、列结构完整；取消保存时界面无提示。
20. 卡片右上角对 R-18 与 AI 作品显示对应徽标，普通作品不显示；多图作品页数徽标同时可见。
21. 切换排序后顺序立即变化并回到第 1 页；「只看未下载」「规则过滤」与排序互不干扰。
22. 点击作品列表「导出」可选择 CSV/JSON，导出内容为当前过滤后的全部作品（跨页），「已下载」列与界面一致。
23. 文件名模板：变量按钮可插入占位符，预览实时变化；缺少 `{id}` 或页码变量时红字报错且下载按钮禁用。
24. 自定义模板下载后的文件名符合模板；标题中的非法字符被替换；去掉 `{ext}` 时仍能正确追加扩展名。
25. 改成自定义模板后，用默认模板下载的历史文件仍被判定为「已下载」。
26. 点击作品列表工具栏的「过滤」图标打开弹窗，调整规则后列表实时变化；图标上的数字等于生效规则条数；关闭弹窗后重启应用规则仍保留。
27. 顶栏「设置」按钮打开设置弹窗，可修改下载质量、动图格式、保存目录、文件名模板并保存 Cookie，关闭后立即落盘；模板非法时下载按钮仍被禁用。
28. 多标签组合：AND 模式下只保留同时含全部标签的作品；OR 模式下保留含任一标签的作品；排除标签生效；目录仍按主标签命名。
29. 左栏「下载质量」切换为常规图/高清原图后，下载按钮文案同步变化，落盘文件分别对应 `regular` 与 `original` 地址；设置弹窗切换与左栏保持一致。
30. 详情弹窗切换「常规图 / 高清原图」时预览图同步变化，默认跟随全局下载质量；点击缩略图在应用内全屏预览，不打开浏览器。
31. 动图作品在卡片与详情显示「动图」徽标；动图格式选 MP4 / GIF / 保留压缩包时分别落盘为同名 `.mp4` / `.gif` / `.zip`，已下载判定、暂停续传与失败重试均正常。
32. 在设置弹窗保存 Cookie 后关闭弹窗，左栏抓取按钮的可用状态与顶部徽标立即更新，无需重启。
33. 下载若干作品后进入「本地图库」，先看到按作者文件夹聚合的作者列表（封面、作者名、作品数、文件数、占用空间与标签）；点击作者进入其作品网格，「全部作者」返回列表；卡片显示封面、标题、`#作品ID`、标签、文件数与占用空间。
34. 作者页搜索只匹配标题与作品 ID（输入作者名或标签不命中），清空后恢复全部；卡片上的 `#作品ID` 可直接复制/输入搜索；无匹配时有空状态提示；结果上千条时滚动流畅，只渲染可视区域的行。
35. 点击图库卡片打开应用内全屏预览，可缩放、旋转、翻转、左右切换，Esc 关闭；`history.json` 缺失时标题回退为「作品 {id}」仍可浏览与预览。
36. 图库内「打开所在文件夹」只允许打开保存目录内的路径；工具栏「重新扫描」能立即反映手动新增或删除的文件。
37. 先用常规图下载某作品，再把质量切换为高清原图并重新下载：长边 1200 的文件被判定为未下载并覆盖重下，日志显示「覆盖」，落盘尺寸变为原图尺寸。

39. 动图作品转码后视频/动图时长与接口返回的帧延迟一致，同目录不残留 `.ugoira-*.zip` 临时文件与 `.part` 文件。

41. 关注列表弹窗关闭后再次打开：5 分钟内直接显示缓存数据并回到上次浏览的页码，不重新请求接口；超过 5 分钟才重新拉取当前页。
42. 同一作品详情弹窗关闭后 10 分钟内再次打开，分页缩略图立即呈现，不重复请求接口。
43. 切换顶部导航标签不会让下载面板的「用时」继续增长；任务结束后用时固定为实际耗时。
44. 设置弹窗调整「请求限流」参数后关闭并重新打开，数值保持不变；重启应用后仍生效，下载时按新并发与间隔执行，遇到 429 依旧先冷却再逐步恢复。

88. 打开他人用户主页显示「关注」按钮，点击后变为「已关注」，再点取关；打开自己的主页不显示该按钮。
89. 设置里填好 client_id / client_secret 后点「通过 pixiv 登录获取」：弹出授权窗口，登录（或已登录直接跳转）后窗口自动关闭，状态变为「已连接」并显示用户 id 与 token 尾号；中途关窗则提示「已取消授权登录」，原有凭据不变。
90. 在浏览记录里右键某作品选「屏蔽该作者」：轻提示「已屏蔽「某某」」；对同一张卡再右键，菜单项变为「取消屏蔽该作者」且不再标红；点击后提示已取消屏蔽，配置里的该词条消失，重新抓取列表后该作者的作品恢复出现。
91. 过滤弹窗点「管理屏蔽名单」：弹出屏蔽管理，分「屏蔽的用户」「屏蔽的标签」两组列出词条并标注匹配方式；删除单条后输入框同步变短，整组「清空」需二次确认；纯数字 ID 行可跳到 pixiv 主页；Esc 只关管理层，不会连过滤弹窗一起关掉。
92. 顶栏「过滤规则」按钮在任意页面（推荐 / 排行榜 / 插画 / 漫画 / 小说 / 用户）都可打开；把「最少页数」设为 3 后当前页不足 3 页的作品立即消失，切到别的栏目同样生效；按钮角标显示生效规则条数。
93. 过滤弹窗里把「内容分级」设为「排除 R-18」：小说搜索结果中的 R-18 作品同时消失（页数 / 尺寸规则不影响小说）；已屏蔽的画师不再出现在用户搜索结果与关注列表里（主进程过滤用户卡）。
94. 某页作品被规则全部挡掉时，网格显示「本页 N 个结果已被过滤规则隐藏」，点其中的「调整规则」直接打开过滤弹窗；清空规则后作品立即恢复，无需重新请求。
