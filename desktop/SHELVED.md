# 功能搁置清单

记录已评估、但当前版本暂不实现的功能，避免需求丢失，也方便后续排期。
已实现功能见 [REQUIREMENTS.md](./REQUIREMENTS.md)，本文件只收录未落地项。

## 搁置项

| 功能 | 优先级 | 搁置原因 | 后续前置条件 |
| --- | --- | --- | --- |
| 多任务并行下载 | P1 | 存储层（`queue.json` 的 `jobs[]`）已支持多任务，卡点在 `ipc.ts` 的 `activeRun` 单例；并行会放大 429 风险 | 先做任务级调度与单任务取消/暂停语义，再评估并发上限 |
| 关注画师批量同步 + 定时任务 + 托盘常驻 | P2 | 三项互相依赖：批量同步需要任务编排，定时需要应用常驻，常驻需要托盘；当前单选一位画师 + 手动「同步收藏夹」已覆盖日常增量备份 | 先明确批量同步的目录归属（按标签还是按画师）；托盘与调度策略（错过执行是否补跑、失败通知）一并设计 |
| SQLite 下载历史库（含 FTS5 检索） | P2 | 已提供 `history.json` 元数据索引，图库有 15s 缓存 + `fs.watch` 增量刷新 + 虚拟滚动，当前规模足够；收益主要在跨维度检索而非性能 | `better-sqlite3` 是原生模块，需确认 Electron ABI 预编译包，否则要 electron-rebuild 与 `asarUnpack`；图库要做复杂组合检索时再迁移 |
| 单张图片 HTTP Range 断点续传 | P2 | 当前按「文件粒度」重下，单文件失败重试成本可接受 | 需要记录已下载字节、校验服务端是否支持 Range |
| 小说（Novel）支持与阅读 | P3 | 现有类型、任务、模板、图库、已下载判定均为插画维度，小说需贯穿全链路；接口需实测（正文走 webview 接口而非 `/ajax/novel/detail`） | 先验证小说接口与正文结构，再决定落盘格式（txt / md）与阅读器形态 |
| 磁盘空间预检 | P3 | 下载前预估体积不准（原图尺寸差异大），收益有限 | 需要稳定的体积估算来源 |
| 多账号 Cookie 切换 | P3 | 单账号场景为主，切换涉及凭据隔离与目录归属 | 需要账号维度的配置与收藏夹目录隔离 |
| 剪贴板监听作品链接 | P3 | 与批量备份主流程关联弱 | 需要链接解析与单作品下载入口 |
| 安装包分发与自动更新 | P3 | 尚未进入分发阶段 | 确定签名、更新源与灰度策略 |
| 排行榜等更多作品来源 | P3 | 作者标签与收藏夹已覆盖主要场景 | 新增来源适配层与对应筛选字段 |
| 失败项逐条手动重试 | P3 | 现有整批重试已能覆盖大多数失败 | 需要更细的任务状态机与去重策略 |
